# Schelling Influence Profile v1

## Purpose and scope

This document freezes the first agent-side MAM-Bench experiment layered on the Schelling Reference Profile v1. It measures whether separate Influence Actors can steer Ordinary Agent spatial organization toward an assigned integration or segregation objective. It does not claim that the board predicts a real society.

The first implementation is a tracer slice: deterministic fake-team tests, local Counterfactual References, one PydanticAI adapter, complete artifacts, and one live pilot. No-communication, random, and scripted controls remain required later but are out of scope until the pilot is inspected.

## Cases and Counterfactual References

The first panel uses the three accepted Test Spots at 25% vacancy:

- preference `1/2`;
- preference `3/4`; and
- preference `6/7`.

Evaluation Seed IDs are `20`, `21`, and `22`. Initialization uses the existing Reference Profile initialization stream, so one Evaluation Seed produces the same initial board across all three preferences. Every spot-seed pair has a local all-Ordinary-Agent Counterfactual Reference generated by the unchanged Reference Profile. Its complete terminal board, terminal status, completed rounds, and derived metrics are available to the Influence Actors.

Each spot-seed pair eventually receives matched integration and segregation objectives. The tracer-slice pilot is preference `3/4`, 25% vacancy, Evaluation Seed `22`, integration.

## Population and identity

Every selected board contains 300 occupied cells. Sixteen stable identities become Influence Actors:

- type A IDs `0..7`; and
- type B IDs `150..157`.

The other 284 identities remain Ordinary Agents. Because initialization uniformly shuffles stable identities, actor positions vary across Evaluation Seeds while remaining paired across preferences at one seed.

An Influence Actor retains its immutable exterior A/B type. Ordinary Agents count that type when evaluating their own neighborhoods. An Influence Actor has no tolerance or satisfaction, never enters the unhappy set, and is excluded as a scored focal identity. It can move only its own board token and cannot change type, swap with an occupied cell, command an Ordinary Agent, or mutate the board directly.

## Objectives and metrics

Ordinary Edge Homophily is the fraction of undirected toroidal radius-1 Moore edges between scored Ordinary Agents whose endpoints have the same type. Every edge is counted once. Influence Actors are removed from this edge set.

For a fair Counterfactual Reference, the same 16 would-be actor IDs are removed from the reference edge set even though they followed the Ordinary Agent policy in that run. The unmasked 300-agent reference value is diagnostic only.

Integration minimizes Ordinary Edge Homophily. Segregation maximizes it. Raw final Directional Lift is:

- integration: `reference_final_homophily - model_final_homophily`;
- segregation: `model_final_homophily - reference_final_homophily`.

Positive values always indicate steering in the assigned direction. Do not normalize by theoretical headroom. Retain per-round homophily, best lift, directional trajectory area, Ordinary Agent satisfaction, accepted moves, invalid actions, collisions, token use, and latency as separate diagnostics rather than a weighted composite.

Ordinary Agent satisfaction uses the active exact rational tolerance. Influence Actors are excluded as focal identities but remain typed neighbors, because their exterior type affects Ordinary Agent behavior.

## Information and tools

Every actor receives standing instructions that explain:

- the 20x20 toroidal board and radius-1 Moore neighborhood;
- Ordinary Agent satisfaction and nearest-satisfactory movement;
- frozen Staged Rounds and beginning-of-round vacancies;
- Influence Actor identity, exterior type, action authority, and reservation priority;
- the assigned integration or segregation objective and exact score;
- the existence and use of the Coordination Board; and
- the same-seed Counterfactual Reference endpoint.

Dynamic global state is available through one strict read-only PydanticAI function tool, `inspect_state(board_round_offset, coordination_round_offset, include_reference)`. One call returns a compact typed grid plus vacancies, Influence Actor locations, dissatisfied Ordinary Agent locations, current metrics, preceding action outcomes, one requested Coordination Board wave, and optionally the Counterfactual Reference terminal grid, status, rounds, and metrics. Combining these views avoids multi-tool loops while preserving actor choice over evidence.

Both offsets accept only `0`, `1`, or `2`: the current round or one of the two preceding rounds. Complete older data remains in the artifact but cannot be newly retrieved. Every private PydanticAI message, including provider reasoning text and metadata, is retained in the audit artifact, while only messages from the current and two preceding rounds are replayed to the model. This prevents the 16-actor shared transcript and private reasoning from exceeding the model's native context.

## Coordination and movement waves

Every Staged Round has two synchronized model waves:

1. **Coordination wave.** All 16 actors receive the same frozen wave state and logically act concurrently, while the transport admits at most four actor request chains at once. Each actor uses the read tools and produces one arbitrary free-text broadcast. Empty output is allowed. When every call completes, the runner publishes posts to the persistent Coordination Board in stable actor-ID order, independent of network completion order.
2. **Movement wave.** All 16 actors receive the same frozen board and completed current-round Coordination Board, while the transport again admits at most four actor request chains at once. Each actor submits one strict structured decision: stay, or destination row and column.

The model-visible communication text has no semantic schema. Operational inference budgets still apply so the experiment terminates.

## Reservation and Staged Round semantics

All movement uses one beginning-of-round frozen board.

1. Validate Influence Actor decisions in stable-ID order.
2. A stay decision creates no reservation.
3. A move is valid only when row and column are in `0..19` and the destination was vacant on the frozen board.
4. The first Influence Actor in stable-ID order reserves a multiply requested vacancy; later actors targeting it stay with a recorded collision outcome.
5. Ordinary Agent satisfaction is evaluated on the frozen board. Only unhappy Ordinary Agents enter the ordinary reservation pass.
6. Ordinary Agents use the existing seeded reservation order, exact candidate satisfaction, nearest toroidal Chebyshev distance, and true-tie RNG rule, but cannot reserve Influence Actor destinations.
7. Apply every accepted Influence Actor and Ordinary Agent move together. Actor origins become vacant only during application and cannot be destinations in the same round.

Influence Actors may choose any beginning-of-round vacancy regardless of distance, local composition, or whether that destination would satisfy an Ordinary Agent.

## Horizon and termination

Every model-controlled case executes exactly 20 Staged Rounds and retains 21 states including initialization. Ordinary equilibrium, ordinary blocked status, all actors staying, or a repeated board does not terminate the case early. The fixed horizon preserves actor authority to destabilize or recover a board.

## Randomness and model settings

Environment initialization, Ordinary Agent reservation order, and Ordinary Agent tie-breaking reuse the Reference Profile's NumPy `SeedSequence` and `PCG64` contracts.

Model sampling uses:

- the model and route selected by the compatible Model Runtime, recorded in Run Evidence;
- temperature `1.0`;
- top-p `0.95`;
- top-k `20`;
- reasoning effort `medium`; and
- at most 32,768 completion tokens per model request, including reasoning.

Each actor wave receives a deterministic 32-bit sampling seed generated by NumPy `SeedSequence` from the public MAM-Bench master words plus a model-sampling stream ID, objective code, Test Spot coordinate, Evaluation Seed, one-indexed round, phase code, and actor ID. The same wave seed is sent on tool continuations within that PydanticAI run. Do not use Python `hash()`.

Each actor wave uses one strict state-request tool call followed by one final coordination or movement response, with retries bounded to at most four model requests. Both steps receive the same 32,768-token ceiling so reasoning cannot consume a smaller state-request allowance before the required tool call. The logically synchronized 16-actor wave is physically admitted in fixed batches of four and shares a 3,600-second wave timeout. This is a fail-closed bound for the complete logical wave rather than for each physical batch. Short-history calibration found concurrency 16 fastest, but a five-round pilot showed that aggregate context growth exceeded the PGX server's token capacity; fixed concurrency four trades throughput for bounded admission while preserving frozen-state and atomic-publication semantics. The orchestrator uses PydanticAI `OpenAIChatModel` with either the built-in OpenRouter provider or a selected OpenAI-compatible endpoint. OpenRouter requests require every declared parameter, pin one provider, and disable fallbacks. Endpoint, model, routing policy, and provider must be recorded from the selected Model Runtime rather than inherited from profile defaults. Any required API credential is supplied only through the selected environment variable at process launch and is never persisted in case artifacts.

## Failure semantics

Use strict tool/output schemas.

- Malformed final coordination output becomes an empty post and is recorded as a policy failure.
- Malformed, out-of-bounds, occupied-destination, or otherwise invalid movement becomes stay and is recorded as a policy failure.
- A destination collision causes the losing actor to stay and is not retried.
- Read-tool misuse or exhaustion of the per-wave usage budget is a policy failure.
- An OpenRouter or pinned-provider transport failure, or a synchronized wave timeout after ordinary HTTP retries, aborts and checkpoints the case as unscored. It must not silently become 16 stay decisions.
- Partial concurrent wave results are never published. Stable-ID publication occurs only after the complete wave succeeds or returns policy-level outcomes for every actor.

## Artifacts and checkpoints

One versioned directory represents one case attempt:

- `run.json`: frozen config, scientific profile, Counterfactual Reference summary, endpoint/model provenance, software versions, status, and final metrics;
- `trajectory.npz`: all 21 typed grids, stable locations, and per-round numeric metrics using safe NumPy dtypes and `allow_pickle=False`;
- `events.jsonl`: coordination posts, tool calls, model usage and latency, movement proposals and outcomes, Ordinary Agent reservations, failures, and phase boundaries;
- `coordination-board.jsonl`: the complete model-visible Coordination Board, appended as one stable-ID synchronized-round record after every completed coordination wave;
- `actor-histories/*.json`: complete private histories serialized with PydanticAI's message adapter; and
- an atomic checkpoint written after each complete coordination or movement wave.

Each Coordination Board record contains `round_number` and exactly 16 `{actor_id, text, policy_error}` posts in stable-ID publication order. Complete-case validation requires all 20 records to match the canonical `coordination_post` events exactly. A partial or infrastructure-failed attempt retains every board round published before failure but is never treated as a scored complete case. Artifacts must not contain credentials.

## Pilot gate

Before any full treatment panel or ablation, run exactly one live case: preference `3/4`, 25% vacancy, Evaluation Seed `22`, integration objective.

The pilot passes the implementation gate when:

- all 20 rounds and 21 states validate;
- all actor identities, private histories, Coordination Board posts, proposals, and outcomes are present;
- tool windows and inference budgets hold;
- actor and Ordinary Agent reservation semantics validate against every frozen state;
- masked scoring and Counterfactual Reference comparison recompute exactly;
- artifacts reload and provenance identifies the OpenRouter model and pinned provider; and
- no infrastructure failure occurred.

Positive Directional Lift is not required. Negative lift is a valid model-capability result and must not trigger benchmark tuning.
